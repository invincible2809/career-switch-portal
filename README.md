# Career-Switch Learning Portal

A self-paced learning portal that helps adults with non-IT backgrounds move into **Scrum Master** or **QA Tester** roles: onboarding with a diagnostic and pathway recommendation, a shared IT Foundations course, role pathways, assessments with explanations and spaced review, and an admin area.

It's built phase by phase from a Claude Code starter kit:

| File | What it is |
|---|---|
| `CLAUDE.md` | Project rules Claude Code loads every session |
| `docs/SPEC.md` | Full product spec |
| `docs/PLAN.md` | Approved build plan (data model, routes, content formats, phase steps, decisions) |
| `docs/PROGRESS.md` | Status log and acceptance-criteria tracker |
| `PHASE-PROMPTS.md` | The prompt to paste for each phase |
| `.claude/agents/content-reviewer.md` | Reviews course content for accuracy and plain English |

**Status:** the MVP is complete (Phases 0–5): onboarding and diagnostic, IT Foundations, Scrum Master and QA Tester Module 1 with practical assignments, the ShopEasy Test Lab with SQL and API sandboxes, a rule-based learning coach, portfolio, career tools, certificate and admin area. All 15 acceptance criteria have passing tests. See `docs/PROGRESS.md` for results and known limitations, and `docs/SECURITY.md` for the security review.

**No AI service is used.** Questions, explanations, coach replies and assignment guidance are generated by rules from course content, so the portal needs no API key and sends no learner data to an AI provider.

## Requirements

- Node.js 20.9 or later (22 recommended)
- pnpm 10
- Docker (for Postgres), or your own PostgreSQL 16

## Setup

```bash
pnpm install                 # also generates the Prisma client
cp .env.example .env         # then set AUTH_SECRET: openssl rand -base64 32
pnpm db:up                   # Postgres on localhost:5433 (creates csp_dev and csp_test)
pnpm db:migrate              # apply migrations
pnpm db:seed                 # import content/ and create the demo accounts
pnpm dev                     # http://localhost:3000
```

Using your own Postgres instead of Docker: point `DATABASE_URL` and `TEST_DATABASE_URL` at two empty databases. The test database name must end in `_test`.

| Variable | Needed | Purpose |

## Tests

```bash
pnpm lint && pnpm typecheck
pnpm content:check # validate content/ without a database
pnpm test          # unit tests (Vitest) – domain logic, content validation, security inventory
pnpm test:e2e      # Playwright end-to-end + axe accessibility checks, against the dev server
pnpm test:e2e:prod # the same suite against a production build (strict CSP, no dev tooling)
```

`pnpm test:e2e` starts its own dev server on port 3100 against `TEST_DATABASE_URL`, applies migrations, empties that database and seeds it. Each acceptance criterion in SPEC §16 has a test – see the table in `docs/PROGRESS.md`. HTML report: `pnpm exec playwright show-report`.

## Course content

Content is written in files under `content/` and imported by `pnpm db:seed`:

```
content/
  pathways.yaml                     pathways, modules ("Coming soon" or available) and module assessments
  glossary.yaml                     shared glossary terms
  lessons/<module>/<nn>-<slug>.md   lessons: front matter + the nine parts as "## Heading {#key}"
  questions/<bank>.yaml             question banks (knowledge checks, module banks, diagnostic)
  assignments/<slug>.md             practical assignment briefs (front matter names the form type and rubric)
  rubrics/<slug>.yaml               rubrics: 4–6 criteria scored 0–3, a minimum rule, optional automated checks
  coach/interview.yaml              mock interview questions and key points
  coach/roleplays.yaml              branching role-play conversations
  coach/cv-guidance.md              CV guidance on the career page
```

- `pnpm content:check` validates every file (nine lesson parts in order, exactly one correct answer for single choice, an explanation for every option, 25+ questions in module banks, links to real lesson sections) without a database.
- In lessons, `[[term]]` or `[[term|label]]` links to the glossary and `:::hint … :::` makes an expandable hint.
- A question can be **generated** instead of written by hand: `generator: who-does-what` or `generator: bva-values` with `params`. Each draw builds a fresh variant with its answer and an explanation for every option (`src/lib/questions/generators.ts`).
- The seed only **adds** things that aren't in the database yet (matched by slug or question key). It never overwrites edits made in the admin area. `pnpm db:reset` rebuilds the dev database from the files – it deletes everything, including learners.
- Run the `content-reviewer` agent on new or changed content before publishing it.

## Admin workflows

Sign in as an admin (see demo accounts) and open **Admin** in the header.

- **Edit a lesson:** Curriculum → module → lesson → *Edit lesson (start a draft)* → save → *Send for review* → *Approve and publish*. Learners keep their place when a new version is published.
- **Edit questions:** Question banks → bank → *Edit question* or *Add a question* (saved as drafts) → *Publish bank changes*. Module banks can't drop below 25 active questions.
- **Pass marks and attempts:** Assessments → assessment. Changes apply to attempts started afterwards.
- **Make a module available:** Curriculum → module → Availability.
- **Assess practical work:** Submissions → submission → score the judgement criteria (and override automated scores if needed). Competency is recorded only when every criterion meets the rubric's minimum. You can also override competency with a reason.
- **Review flagged items:** Review queue – coach answers, lessons and questions learners have flagged.
- **Reports:** progress by module, most-failed questions and common gaps (totals only).
- **Users:** change roles (this signs the person out). Everything above is in the **Audit log**.

## Adding course content

- **Lessons:** add `content/lessons/<module>/<nn>-<slug>.md` with front matter and the nine parts (see an existing lesson). Each needs a knowledge-check bank.
- **Question banks:** `content/questions/<slug>.yaml`. Module banks need 25+ questions; every option needs an explanation; every question links to a lesson section for remediation.
- **Question generators:** add a function to `src/lib/questions/generators.ts` that builds the question, its answer and an explanation for each option from a seed, register it in `GENERATORS`, add unit tests (see `tests/unit/generators.test.ts`), then use it in a bank with `generator:` and `params:`.
- **Assignments and rubrics:** `content/assignments/<slug>.md` (front matter: module, form type, rubric) and `content/rubrics/<slug>.yaml` (4–6 criteria, 0–3, `minimumRule`). Automated checks are named functions in `src/server/assignments/checks.ts`. A new form type needs a form component and a payload schema in `src/lib/assignments/forms.ts`.
- **Coach:** interview questions and role-plays live in `content/coach/*.yaml`; the coach's answers come from published lessons and the glossary automatically.
- Then run `pnpm content:check`, `pnpm test`, and the **content-reviewer** agent, and import with `pnpm db:seed` (it adds new items and never overwrites admin edits).

## Before going live

- [ ] Choose hosting with HTTPS and managed PostgreSQL; set `APP_URL` to the public HTTPS address and a strong `AUTH_SECRET`.
- [ ] Run migrations with `pnpm db:deploy` (not `db:migrate`) and seed course content. Don't create the demo accounts in a real environment, or remove them first.
- [ ] Connect real email (`SMTP_*`) and leave `ALLOW_DEMO_MAILBOX` unset.
- [ ] Make sure the proxy in front of the app sets `X-Forwarded-For` correctly (used by rate limits).
- [ ] Decide on the open items in `docs/SECURITY.md` (registration message, MFA for admins).
- [ ] Add the operator's contact details and lawful basis to the privacy notice (`src/app/privacy/page.tsx`).
- [ ] Have a subject expert review the course content (it has been checked by the content-reviewer agent, not by a person).
- [ ] Run `pnpm test:e2e:prod` and `pnpm audit --prod`.
