# Career-Switch Learning Portal

A self-paced learning portal that helps adults with non-IT backgrounds move into **Scrum Master** or **QA Tester** roles: onboarding with a diagnostic and pathway recommendation, a shared IT Foundations course, role pathways, assessments with explanations and spaced review, and an admin area.

It's built phase by phase from a Claude Code starter kit:

| File | What it is |
|---|---|
| `CLAUDE.md` | Project rules Claude Code loads every session |
| `docs/SPEC.md` | Full product spec |
| `docs/PLAN.md` | Approved build plan (data model, routes, content formats, phase steps, decisions) |
| `docs/PROGRESS.md` | Status log and acceptance-criteria tracker |
| `PHASE-PROMPTS.md` | The prompt to paste for each phase |
| `.claude/agents/content-reviewer.md` | Reviews course content for accuracy and plain English |

**Status:** Phases 0–4 are done (core platform, Foundations, Scrum Master and QA Tester Module 1 with practical assignments, the ShopEasy Test Lab with SQL and API sandboxes, the rule-based coach, portfolio, career tools and certificate). Phase 5 (hardening and handover) is next. See `docs/PROGRESS.md`.

**No AI service is used.** Questions, explanations, coach replies and assignment guidance are generated by rules from course content, so the portal needs no API key and sends no learner data to an AI provider.

## Requirements

- Node.js 20.9 or later (22 recommended)
- pnpm 10
- Docker (for Postgres), or your own PostgreSQL 16

## Setup

```bash
pnpm install                 # also generates the Prisma client
cp .env.example .env         # then set AUTH_SECRET: openssl rand -base64 32
pnpm db:up                   # Postgres on localhost:5433 (creates csp_dev and csp_test)
pnpm db:migrate              # apply migrations
pnpm db:seed                 # import content/ and create the demo accounts
pnpm dev                     # http://localhost:3000
```

Using your own Postgres instead of Docker: point `DATABASE_URL` and `TEST_DATABASE_URL` at two empty databases. The test database name must end in `_test`.

### Demo accounts

| Role | Email | Password |
|---|---|---|
| Learner | `learner@demo.local` | `LearnDemo2026!` |
| Admin | `admin@demo.local` | `AdminDemo2026!` |

Passwords come from `DEMO_LEARNER_PASSWORD` and `DEMO_ADMIN_PASSWORD` in `.env` – change them for any shared environment. The demo learner starts at onboarding.

### Environment variables

All are listed with comments in `.env.example`.

| Variable | Needed | Purpose |
|---|---|---|
| `DATABASE_URL` | Yes | App database |
| `TEST_DATABASE_URL` | For e2e tests | Separate database, **emptied on every e2e run**; name must end in `_test` |
| `AUTH_SECRET` | Yes | Signs session cookies |
| `APP_URL` | Yes | Base URL used in password-reset links |
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASSWORD`, `SMTP_FROM` | No | Real email. Leave `SMTP_HOST` empty for **demo mode**: reset emails appear at `/dev/mailbox` instead |
| `ALLOW_DEMO_MAILBOX` | No | The demo mailbox is off in production builds unless this is `true` |
| `DEMO_LEARNER_PASSWORD`, `DEMO_ADMIN_PASSWORD` | For seeding | Demo account passwords |

## Tests

```bash
pnpm lint && pnpm typecheck
pnpm test          # unit tests (Vitest) – pure domain logic, content validation, guard coverage
pnpm test:e2e      # Playwright end-to-end + axe accessibility checks
```

`pnpm test:e2e` starts its own dev server on port 3100 against `TEST_DATABASE_URL`, applies migrations, empties that database and seeds it. Each acceptance criterion in SPEC §16 has a test – see the table in `docs/PROGRESS.md`. HTML report: `pnpm exec playwright show-report`.

## Course content

Content is written in files under `content/` and imported by `pnpm db:seed`:

```
content/
  pathways.yaml                     pathways, modules ("Coming soon" or available) and module assessments
  glossary.yaml                     shared glossary terms
  lessons/<module>/<nn>-<slug>.md   lessons: front matter + the nine parts as "## Heading {#key}"
  questions/<bank>.yaml             question banks (knowledge checks, module banks, diagnostic)
  assignments/<slug>.md             practical assignment briefs (front matter names the form type and rubric)
  rubrics/<slug>.yaml               rubrics: 4–6 criteria scored 0–3, a minimum rule, optional automated checks
  coach/interview.yaml              mock interview questions and key points
  coach/roleplays.yaml              branching role-play conversations
  coach/cv-guidance.md              CV guidance on the career page
```

- `pnpm content:check` validates every file (nine lesson parts in order, exactly one correct answer for single choice, an explanation for every option, 25+ questions in module banks, links to real lesson sections) without a database.
- In lessons, `[[term]]` or `[[term|label]]` links to the glossary and `:::hint … :::` makes an expandable hint.
- A question can be **generated** instead of written by hand: `generator: who-does-what` or `generator: bva-values` with `params`. Each draw builds a fresh variant with its answer and an explanation for every option (`src/lib/questions/generators.ts`).
- The seed only **adds** things that aren't in the database yet (matched by slug or question key). It never overwrites edits made in the admin area. `pnpm db:reset` rebuilds the dev database from the files – it deletes everything, including learners.
- Run the `content-reviewer` agent on new or changed content before publishing it.
